Un agente = modelo + prompt + permisos

"agent": {
  "architect": {
    "mode": "subagent",
    "prompt": "Eres el arquitecto del proyecto...",

  }
}

mode: primary · subagent · all (por defecto)

Subagentes

@reviewer revisa este cambio y dime qué se me escapa
  • Contexto separado: no ensucia tu conversación
  • Con edit: deny: revisa sin poder tocar
  • @ hace doble función: ficheros y subagentes
Quien revisa, no arregla.

permission.task — a quién puede llamar cada uno

"permission": {
  "task": {
    "*": "deny",
    "architect": "allow",
    "developer": "allow"
  }

Bloque 8. Minuto 43. Ya se enseñó en el tour: aquí se explica.

La precedencia: qué es

Las reglas pueden estar en varios sitios. opencode los mira en orden y se queda con el primero que encuentra.

OrdenDónde
1AGENTS.md del proyecto (subiendo por el árbol)
2~/.config/opencode/AGENTS.md global
3~/.claude/CLAUDE.md (compatibilidad)

Cuál uso

Proyecto → las reglas del equipo. Se commitea y las comparten todos.

Global → tus manías personales. Cómo te gusta que te responda, en qué idioma.

Si escribes una convención del equipo en tu fichero global, tú trabajarás bien y tus compañeros no. Y encima no te vas a dar cuenta.

Bloque 11. Minuto 58. La demo estrella.

Skills

Procedimientos reutilizables que el agente carga cuando ve que aplican.

.opencode/skills/i18n/SKILL.md

---
name: i18n
description: Procedimiento obligatorio para añadir o cambiar
  cualquier texto visible de la interfaz. Úsalo siempre que una
  tarea implique mostrar texto al usuario.
---
1. Añade la clave en `src/i18n/es.json`
2. Usa `t('clave')`, nunca el literal

name debe coincidir con la carpeta.

Cómo funciona por dentro

El agente solo ve una lista de nombres y descripciones.

Si le encaja, llama a la herramienta skill y entonces carga el contenido.

La descripción es lo único que ve antes de decidir. Si está mal escrita, el skill no se usa nunca.

Se escribe pensando en cuándo activarlo, no en qué contiene.

Cuál de las tres uso

Quién lo activaCuándoCoste
AGENTS.mdSiempre cargadoAplica a todoSiempre
ComandoTú, con /nombreTareas que tú disparasCero
SkillEl agenteProcedimientos ocasionalesSolo la descripción

Si aplica siempre → AGENTS.md. Si lo lanzas tú → comando. Si aplica a veces y el agente puede reconocer cuándo → skill.

MCP · Model Context Protocol

Un estándar para darle herramientas nuevas al agente.

"mcp": {
  "playwright": {
    "type": "local",
    "command": ["npx", "-y", "@playwright/mcp@latest"]
  }
}

Remoto por URL, o local por comando. Tres líneas.
